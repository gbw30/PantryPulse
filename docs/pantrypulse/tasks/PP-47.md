# PP-47 — Audited stock adjustment HTTP API

Owner: lead for VaishnaviPhadtare. Authorized by the request to write the next API.
Base: db94a95 on local VP, with the uncommitted PP-46 inventory snapshot preserved.

Expose `POST /api/v1/inventory/sites/{site_id}/products/{product_id}/adjustments`.
Use the existing presenter session, allowed Origin, CSRF and Idempotency-Key.
Body: saved expected inventory version, nonblank reason, source reference and
1–100 unique existing-lot deltas. Versions/deltas use canonical decimal strings
to preserve browser precision, with the existing signed-BIGINT bounds. Zero
deltas, unknown fields, mismatched lot/site/product and cross-tenant lots fail.
Tenant/actor come from authentication, never request JSON.

Adapt to the existing AdjustStock/execute_stock service; do not rewrite stock
arithmetic. One caller-owned transaction commits stock, version, command, ledger
and audit together. Return a typed committed outcome with exact before/after
quantities. Exact replay returns the saved outcome without a second adjustment;
changed payload under the same key and stale versions return 409. Negative stock
returns 422 with no writes. Only existing lots can be adjusted: creation/receipts
are separate APIs. No worker, frontend screen, schema change or persistent demo
stock mutation is included.

Write boundary: inventory HTTP schema/router, adjustment adapter, error mapping,
focused tests, proxy allowlist, generated contracts and flow/task/board docs.
Acceptance: failing DTO tests first; actual PostgreSQL/HTTP tests for audit,
idempotency, stale/concurrent updates, rollback, tenant/lot scope and security;
snapshot regression; backend regression/lint, proxy tests, web types/lint and
offline contract drift. Isolate DB tests to generated disposable schemas.
Independent release review and full browser integration remain separate gates.
Do not push/deploy. Diagnose after two different failed fixes.
